# Hive Release v0.1.1 (2026-04-04)

## Summary

v0.1.1 standardizes session-target envelope behavior across hive-cli and hive-daemon, removes temporary runtime compatibility shims, and adds strict startup compatibility checks in the CLI.

## What changed

1. Protocol/runtime alignment
   1.1 `hive_daemon.envelope.create_envelope()` now supports `target_session`.
   1.2 Envelope JSON now carries `targetSession` when present.

2. CLI send path hardening
   2.1 Removed fallback shim in `hive-cli send` that tolerated older daemon APIs.
   2.2 `send` now always passes `target_session`.

3. Compatibility checks (fail fast)
   3.1 `hive-cli` now enforces `hive-cli>=0.1.1` and `hive-daemon>=0.1.1` at startup.
   3.2 `hive-cli` verifies `create_envelope()` includes `target_session`; otherwise exits with a clear error.

4. Versioning
   4.1 `hive-cli` bumped to `0.1.1`.
   4.2 `hive-daemon` bumped to `0.1.1`.
   4.3 CLI dependency pinned to `hive-daemon>=0.1.1,<0.2.0`.

## Operational notes

1. This release intentionally removes mixed-version tolerance for session-targeted send behavior.
2. Upgrade/reinstall both CLI and daemon packages together on each host.
3. If startup fails, check local venv package versions and editable install targets first.

## Verification snapshot

Cluster rollout + smoke checks were completed after release:

1. All hive repos synced to the same commit/tag.
2. `hive-cli` and `hive-daemon` report `0.1.1` on `turq`, `pg1`, and `turqette`.
3. Cross-host `hive-cli send --wait` roundtrips pass.
4. Discord deterministic RPC sends pass from `pg1`, `turq`, `turqette`, and `mini1` daemon route.
